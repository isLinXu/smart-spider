# ADR-0001：采用持久化数据集任务编排器

## 状态

Accepted

## 背景

当前 `DatasetCrawler` 依赖进程内队列、计数器和文件状态，适合小规模实验，但在几千到几十万张图片任务中，任务恢复、失败重试、并发编号和数据一致性风险会明显增加。

## 决策

采用“持久化任务编排器 + 可插拔 Worker”架构。第一阶段使用 SQLite WAL 保存任务状态，使用本地文件系统保存图片和 JSONL/Parquet manifest；未来再替换为分布式队列或对象存储。

## 结果

### 正面

- 支持任务中断恢复和失败重试；
- 任务状态、模型结果和错误可审计；
- 单机与多进程可以复用同一套接口；
- 避免过早引入 Redis/Kafka/Kubernetes。

### 负面

- 需要设计状态机、租约和幂等写入；
- SQLite 在极高并发下有写入瓶颈；
- 初期实现复杂度高于单纯线程池。

## 备选方案

- 继续扩展单进程 `DatasetCrawler`：改动小，但不适合长期任务。
- 直接建设微服务：扩展性更强，但当前运维成本和复杂度过高。

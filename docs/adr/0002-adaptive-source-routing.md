# ADR-0002：采用静态搜索优先、Browser Use 自适应兜底

## 状态

Accepted

## 背景

静态 HTTP 请求吞吐高、成本低，但容易受到 JS 渲染、懒加载、登录态和反爬限制；Browser Use 适应性强，但启动和推理成本高，不适合所有 URL。

## 决策

来源路由默认采用：

```text
静态请求/搜索
→ 响应质量检测
→ Browser Use 动态探索
→ 备用来源或人工复核
```

路由器根据状态码、HTML 长度、结果数量、登录/验证码迹象、资源发现率和历史成功率进行切换。Browser Use 只负责探索和候选发现，最终下载、质量过滤、去重和写盘仍由确定性管线完成。

## 结果

### 正面

- 大多数请求保持低成本和高吞吐；
- 动态网站和未知页面结构有兜底能力；
- LLM 不直接控制数据一致性；
- 可以按域名记录路由成功率，持续优化策略。

### 负面

- 需要维护静态和浏览器两套适配器；
- Browser Use 的探索结果存在不确定性；
- 需要限制浏览器预算，避免任务成本失控。

## 备选方案

- 所有页面都使用浏览器：实现简单但成本高、吞吐低。
- 只使用静态解析器：吞吐高但对动态和未知站点适应性不足。
